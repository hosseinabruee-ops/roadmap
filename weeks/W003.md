۱. سه ناحیه‌ی Git چیست و فایل چطور بین آن‌ها حرکت می‌کند؟
سه ناحیه‌ی اصلی Git عبارت‌اند از:

Working Directory (پوشه‌ی کار): پوشه‌ای که فایل‌ها را در آن ویرایش و ذخیره می‌کنیم.

Staging Area / Index (ناحیه‌ی آماده‌سازی): ناحیه‌ای میانی که تغییرات انتخاب‌شده برای commit بعدی در آن قرار می‌گیرند.

Repository (مخزن): جایی که commitها و تاریخچه‌ی پروژه به‌صورت دائمی ذخیره می‌شوند.

حرکت فایل بین این سه ناحیه:

text
ویرایش در Working Directory
        ↓ git add
ورود به Staging Area
        ↓ git commit
ثبت در Repository
برای بررسی هر مرحله از git status، git diff و git diff --staged استفاده می‌کنیم.

۲. Git و GitHub چه فرقی دارند؟
Git یک ابزار کنترل نسخه‌ی توزیع‌شده است که به‌صورت محلی روی سیستم کار می‌کند و تاریخچه‌ی پروژه را نگه می‌دارد. Git بدون اینترنت هم کار می‌کند.

GitHub یک سرویس میزبانی آنلاین برای مخازن Git است که امکانات همکاری مثل issue، pull request، code review و remote را فراهم می‌کند.

به بیان ساده: Git ابزار است، GitHub سرویس. Git بدون GitHub هم کار می‌کند، اما GitHub بدون Git معنا ندارد.

۳. commit چه چیزی را ثبت می‌کند و چرا پیام مهم است؟
هر commit یک snapshot از تغییرات stage شده را ثبت می‌کند، همراه با متادیتا مثل:

نام و ایمیل نویسنده

تاریخ و زمان

پیام commit

اشاره به commit والد (تاریخچه)

یک hash یکتا (SHA)

پیام commit مهم است چون:

تاریخچه را خوانا و قابل فهم می‌کند.

دلیل تغییرات را برای خودت و دیگران روشن می‌کند.

در بازبینی، عیب‌یابی و جست‌وجو کمک می‌کند.

در همکاری تیمی، فهم کار دیگران را ساده‌تر می‌کند.

پیام خوب کوتاه، روشن و با فعل امری نوشته می‌شود؛ مثل «افزودن README».

۴. .gitignore چه کاری می‌کند؟
فایل .gitignore به Git می‌گوید کدام فایل‌ها و پوشه‌ها را نادیده بگیرد و track نکند. این کار از commit شدن فایل‌های موقت، حجیم، محرمانه یا غیرضروری جلوگیری می‌کند و ریپو را تمیز نگه می‌دارد.

مثال:

gitignore
sandbox/
git-practice/
*.tmp
.env
secrets/
node_modules/
__pycache__/
.DS_Store
اگر فایلی قبلاً commit شده باشد، اضافه کردن آن به .gitignore به‌تنهایی کافی نیست؛ باید با git rm --cached از track خارج شود.

۵. چرا نباید رمز یا توکن را commit کرد؟
چون تاریخچه‌ی Git ماندگار است و پس از push، در remote و cloneهای دیگر باقی می‌ماند. حتی اگر فایل را حذف کنی، نسخه‌ی قبلی در تاریخچه باقی می‌ماند و هر کسی با دسترسی به ریپو می‌تواند آن را ببیند.

خطرها:

سوءاستفاده از رمز یا توکن

دسترسی غیرمجاز به سرویس‌ها

آسیب به داده‌ها یا حساب‌ها

مشکل حقوقی و امنیتی

اگر رمزی commit شد:

۱. فوراً آن را باطل کن.
۲. رمز یا توکن جدید بساز.
۳. از فایل .env یا secret manager استفاده کن.
۴. .env و فایل‌های محرمانه را در .gitignore بگذار.
۵. در صورت نیاز، تاریخچه را بازنویسی کن (مثلاً با git filter-repo).

۶. چه چیزی این هفته سخت‌تر از انتظار بود؟
در ابتدا تفاوت git diff و git diff --staged کمی گیج‌کننده بود و نمی‌دانستم تغییرات کجا قرار گرفته‌اند.
